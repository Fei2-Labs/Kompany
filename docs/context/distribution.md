# Distribution — Kompany desktop app

Status: v1 (Tauri 2.x shell + Python sidecar). Source tree only; CI
builds and signed releases are out of scope for this task.

## Architecture

```
+--------------------------------------------------+
|  Kompany.app  (native window, no browser chrome) |
|  +--------------------------------------------+  |
|  |  Tauri WebView                             |  |
|  |  http://127.0.0.1:<random_port>/ui/        |  |
|  |  (cyberpunk SPA — same code as web build)  |  |
|  +--------------------------------------------+  |
|                       ^                          |
|                       | (HTTP / SSE on loopback) |
|                       v                          |
|  +--------------------------------------------+  |
|  |  Python sidecar (PyInstaller --onedir)     |  |
|  |  kompany-server-<target-triple>            |  |
|  |    --port <random> --data-dir <app_data>   |  |
|  |  → uvicorn (kompany.interfaces.api:app)    |  |
|  |  → SQLite at <app_data>/kompany.db         |  |
|  +--------------------------------------------+  |
+--------------------------------------------------+
```

The Rust shell does three jobs:

1. Pick a free loopback port via `TcpListener::bind("127.0.0.1:0")`.
2. Spawn the sidecar binary; poll `/health` until 200 (30s budget).
3. Build a WebView pointing at the sidecar; kill the sidecar on close.

All business logic stays in Python. The Rust code path is intentionally
~200 lines and contains no Kompany domain logic.

## Build prerequisites

Run these once per developer machine before the first
`build_desktop.sh`:

```bash
# 1. Rust toolchain + Tauri CLI 2.x
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh
cargo install tauri-cli --version "^2.0"

# 2. Python build deps for the sidecar
python -m pip install -e 'kompany[api,desktop]'

# 3. Platform-specific system packages
#    macOS:    xcode-select --install
#    Linux:    sudo apt-get install \
#                libwebkit2gtk-4.1-dev \
#                libssl-dev \
#                libayatana-appindicator3-dev \
#                librsvg2-dev \
#                libgtk-3-dev \
#                build-essential
#    Windows:  WebView2 runtime (ships with Win11; install on Win10)
```

## One-shot build

From the repo root:

```bash
./kompany/build_desktop.sh
```

This runs three stages:

1. `kompany/build_sidecar.sh` — PyInstaller `--onedir` bundle named
   `kompany-server-<target-triple>` under `kompany/dist/`.
2. Copy that into `tauri/src-tauri/binaries/` so Tauri's
   `externalBin` discovery finds it.
3. `cargo tauri build` from `tauri/`. Installers land at
   `tauri/src-tauri/target/release/bundle/` (`dmg/`, `msi/`, `appimage/`).

The target triple is read from `rustc -vV` (override with
`KOMPANY_TARGET_TRIPLE=…` if cross-compiling).

## Icons

A placeholder neon-K is generated by:

```bash
python tauri/icons/generate_placeholder.py
```

Replace `tauri/icons/icon.png` with a designer asset, then run:

```bash
cd tauri && cargo tauri icon icons/icon.png
```

to materialise the per-platform multi-size icon set.

## Data directory

The shell calls Tauri's `app_data_dir()` and passes the result to the
sidecar via `--data-dir`. Per platform defaults:

| Platform | Path                                              |
|----------|---------------------------------------------------|
| macOS    | `~/Library/Application Support/com.kompany.desktop/` |
| Linux    | `~/.local/share/com.kompany.desktop/`             |
| Windows  | `%APPDATA%\com.kompany.desktop\`                  |

The sidecar exports `KOMPANY_DATA_DIR` into the env so
`KompanySettings` and the credentials vault find the right SQLite
file.

## Code signing — v2

v1 builds are unsigned. First-launch instructions:

* **macOS**: right-click → Open the first time, or
  `xattr -dr com.apple.quarantine /Applications/Kompany.app`.
* **Windows**: SmartScreen → "More info" → "Run anyway".
* **Linux**: `chmod +x Kompany.AppImage`.

## Platform notes

* **macOS Apple Silicon vs Intel**: ship two dmgs (separate
  `cargo tauri build` runs with `--target aarch64-apple-darwin` and
  `--target x86_64-apple-darwin`). A universal2 build is possible but
  doubles the sidecar size (PyInstaller is per-arch).
* **Windows**: WebView2 is the runtime. Win10 fresh installs need
  Microsoft's redistributable; bundle via Tauri's
  `windows.webviewInstallMode` if necessary.
* **Linux**: AppImage runs on any glibc >= 2.31 distro. We do not ship
  a `.deb` / `.rpm` v1.

## Edge cases handled by the shell

* **Port collision**: `TcpListener::bind("127.0.0.1:0")` is a tight
  TOCTOU window; if `/health` doesn't come up in 30s we retry once
  with a freshly-picked port.
* **Sidecar crash on launch**: surfaced as an `Err(...)` from the
  Tauri `setup` hook — Tauri shows a native error dialog rather than
  silently opening an empty window.
* **Multiple instances**: v1 doesn't single-instance. A second launch
  will fail health-check, kill its own sidecar, and exit. v2 should
  add `tauri-plugin-single-instance`.

## Smoke test (manual)

After `build_desktop.sh` on macOS:

```bash
open tauri/src-tauri/target/release/bundle/dmg/Kompany_0.1.0_aarch64.dmg
# Drag into /Applications; right-click → Open the first time.
```

Expected:

1. Window opens within 5s, no terminal, no browser tab.
2. First-launch shows the cyberpunk onboarding form.
3. Submitting valid credentials → "Provisioning…" → main dashboard.
4. Closing the window also terminates the sidecar process
   (`ps -ef | grep kompany-server` returns nothing).
